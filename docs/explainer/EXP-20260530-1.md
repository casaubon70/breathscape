## 1. Nativer Sync

### Architektur

```
SyncedKeyValueStore (Interface)
├── LocalKeyValueStore      (shared_preferences, immer vorhanden)
├── ICloudKeyValueStore     (iOS + macOS, kein Sign-in)
└── DriveAppDataStore       (Android, OAuth via google_sign_in)
```

`PatternOverridesRepository` hält beide Stores. Lesen: last-writer-wins via `PatternOverrides.updatedAt`. Schreiben: lokal-first, remote best-effort.

### `ICloudKeyValueStore`

Zwei native Channels, eine pro Plattform eingebettet:

| Channel | Typ | Richtung | Verwendung |
|---------|-----|----------|-----------|
| `breathscape/icloud_kv` | MethodChannel | Flutter → Native | `get` / `set` |
| `breathscape/icloud_kv_changes` | EventChannel | Native → Flutter | Key, dessen Wert sich auf einem anderen Gerät geändert hat |

`watch(key)` filtert den EventChannel auf den angefragten Key, liest den neuen Wert nach und schließt leere Antworten aus:

```dart
Stream<String> watch(String key) {
  return _changes
      .receiveBroadcastStream()
      .where((event) => event == key)
      .asyncMap((_) async => await read(key) ?? '')
      .where((value) => value.isNotEmpty);
}
```

Native Implementierungen: `AppDelegate.swift` (iOS) und `MainFlutterWindow.swift` (macOS) registrieren `NSUbiquitousKeyValueStore`-Observer und emittieren den geänderten Key auf dem EventChannel.

### `DriveAppDataStore`

Verwendet die Drive REST API direkt (kein `googleapis`-Paket). Jeder Key wird als einzelne JSON-Datei im `appDataFolder` gespeichert (`{key}.json`). `write` prüft zuerst, ob die Datei existiert (`_fileId`), und führt dann POST (neu) oder PATCH (Update) aus. `watch` gibt `Stream.empty()` zurück – Drive bietet keinen günstigen Push-Kanal; Cross-Device-Sync passiert beim App-Start.

Der Access-Token wird per `AccessTokenProvider`-Typedef injiziert, was Unit-Tests ohne echten Google Sign-in ermöglicht.

### `createRemoteSyncStore()`

```dart
SyncedKeyValueStore? createRemoteSyncStore() {
  if (kIsWeb) return null;          // Web-Guard (s. Fix unten)
  switch (defaultTargetPlatform) {
    case TargetPlatform.iOS:
    case TargetPlatform.macOS: return const ICloudKeyValueStore();
    case TargetPlatform.android: return DriveAppDataStore(...);
    default: return null;
  }
}
```

## 2. Web-Fix (`pattern_overrides_repository.dart`)

### Problem

Auf Web gibt `defaultTargetPlatform` das Host-OS zurück (z. B. `macOS`). Ohne `kIsWeb`-Guard wählte die Factory `ICloudKeyValueStore`, dessen `MethodChannel` auf Web nicht existiert. Der `read`-Call warf, `PatternsBloc` landete in `failure`, und der Spinner lief endlos.

### Lösung

Zweistufige Absicherung:

1. `kIsWeb` in `createRemoteSyncStore()` → gibt immer `null` zurück.
2. `PatternOverridesRepository.load()` fängt alle Remote-Fehler und fällt auf das lokale Ergebnis zurück:

```dart
try {
  remote = _parse(await remoteStore.read(storageKey));
} on Object {
  remote = null;     // Fehler ≠ Blocker
}
```

Gleiches Muster in `save()` und über `.handleError((_) {})` im `changes`-Stream. Ein fehlender oder fehlerhafter nativer Sync-Provider degradiert gracefully zu local-only.

## 3. Inline-Edit-Modus (`breathing_session_page.dart`)

### Layout-Strategie

Edit-Modus und Normal-Modus teilen denselben `_buildSessionArea`-Wrapper. Der Unterschied: `_buildNormalStack` vs. `_buildEditStack`.

**Normal**: Animation zentriert, `VoiceMuteButton` rechts davon in der freien Hälfte.

**Edit**: `Stack` mit `clipBehavior: Clip.none` enthält zwei unabhängige Kinder:
- `Center` → Animation-BlocBuilder (feuert jeden Frame)
- `Positioned.fill` → Adjuster-BlocBuilder (feuert nur bei Pattern-Änderung)

Da beide Geschwister im selben Stack sind, löst der Frame-taktende Animation-Builder keinen Rebuild der Adjuster-Rows aus.

### Geometrie der Adjuster-Positionierung

```dart
final adjustersLeft = ((maxWidth + circleSize) / 2 + spacing.m)
    .clamp(0.0, maxWidth - spacing.m);
```

`(maxWidth + circleSize) / 2` ist der rechte Rand der zentrierten Animation. `clamp` verhindert negative Breite auf sehr schmalen Screens.

Jede Adjuster-Row wird per `Positioned(top: centerY(type) - rowHalfHeight, ...)` vertikal an ihr visuelles Gegenstück ausgerichtet:

```dart
double centerY(PhaseType type) => switch (type) {
  PhaseType.holdIn     => circleSize * 0.5,
  PhaseType.inhale     => barTop + animHeight * 0.3,
  PhaseType.exhale     => barTop + animHeight * 0.7,
  PhaseType.holdOut    => barTop + animHeight + barGap + circleSize * 0.5,
  PhaseType.extendedExhale => barTop + animHeight * 0.7,
};
```

### `PatternDurationUpdated`-Event

Neues Event in `BreathingBloc`: Aktualisiert Phasendauern während einer laufenden Session, ohne Ticker oder Phase-Index zurückzusetzen.

```dart
void _onPatternDurationUpdated(PatternDurationUpdated event, ...) {
  _pattern = event.pattern;
  // Clamp: verhindert Kaskaden-Phase-Skips wenn Duration auf < elapsed reduziert.
  final newDuration = _effectivePhase(_phaseIndex, _cycle).duration;
  if (_phaseAccumulated >= newDuration) {
    _phaseAccumulated = newDuration - const Duration(microseconds: 1);
  }
  ...
}
```

### UI-Änderungen

- `PlaybackControls.onReset` ist jetzt nullable. Im Edit-Modus wird `null` übergeben → Reset-Icon verschwindet. Stattdessen erscheint links ein `RESET`-TextButton, der `PatternReset` auf dem `PatternsBloc` auslöst.
- `CycleDotRow` ist im Edit-Modus mit `Opacity(0.0)` versteckt statt mit `if`-Branch entfernt, damit `animHeight` beim Umschalten stabil bleibt.
- `BreathingAnimationWidget` exponiert `kCircleRatio = 0.375` und `kBarGap = 16.0` als statische Konstanten – der Edit-Stack berechnet seine Geometrie daraus, ohne Magic Numbers zu duplizieren.

## 4. Rebuild-Performance (`breathing_session_page.dart`)

### Problem

Ein einzelner `BlocBuilder` in `_buildSessionArea` umschloss Animation, Phasen-Info und Adjuster-Rows. Da `fillLevel` jeden Frame emittiert, bauten alle drei bei 60 fps neu – auch die Adjuster, deren Inhalt sich nur bei Taps ändert.

### Lösung: Drei unabhängige BlocBuilder

| Builder | `buildWhen` feuert bei | Frequenz |
|---------|------------------------|----------|
| Phasen-Info | `phaseSecondsRemaining`, `currentPhase`, `status` | ~1×/s |
| Animation | `fillLevel`, `circleScale`, `circleOpacity`, `deepZoneFill`, … | jeden Frame |
| Adjuster | `selectedPattern` | nur bei Tap |

`_isAnimChange` ist als statische Methode extrahiert und von beiden Layout-Pfaden (Normal + Edit) geteilt.

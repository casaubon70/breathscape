## Was wurde geändert?

Dieses Inkrement fügt Session-Tracking, Cycle-Completion und ein überarbeitetes Playback-UI hinzu. Die App kennt jetzt ein Ende einer Session (alle Zyklen durchlaufen), zeigt einen Gesamt-Countdown sowie einen Zyklus-Counter an, und das Playback-Control-Widget wurde symmetrisch zentriert und um einen Settings-Button ergänzt. Die Animation und das Dropdown wurden vollständig auf Theme-Tokens umgestellt (bisher hardcodierte Hex-Farben).

## Datenmodell

### `BreathingPattern` – neues Feld `defaultCycles`

```dart
class BreathingPattern extends Equatable {
  const BreathingPattern({
    required this.name,
    required this.phases,
    this.defaultCycles = 10,
  });

  factory BreathingPattern.fromMap(Map<dynamic, dynamic> map) {
    return BreathingPattern(
      ...
      defaultCycles: (map['default_cycles'] as int?) ?? 10,
    );
  }

  final int defaultCycles;
}
```

`defaultCycles` definiert wie viele Zyklen eine Session umfasst. Default: 10. Wird aus YAML (`default_cycles`) gelesen; fehlt der Key, greift der Default. In `breathing_patterns.yaml` ist `default_cycles: 10` bei allen drei Patterns explizit gesetzt.

### `SessionStatus` – neuer Wert `completed`

```dart
enum SessionStatus { idle, playing, paused, completed }
```

`completed` wird emittiert, wenn der letzte Zyklus abgelaufen ist. Unterscheidet sich von `idle` (noch nie gestartet oder zurückgesetzt) und `paused` (manuell angehalten).

### `BreathingState` – neues Feld `sessionSecondsRemaining`

```dart
final class BreathingState extends Equatable {
  const BreathingState({
    ...
    this.sessionSecondsRemaining = 0,
  });

  final int sessionSecondsRemaining;
}
```

Gesamte verbleibende Session-Zeit in ganzen Sekunden. Startet bei `defaultCycles × Zyklusdauer`. Zählt bei jedem Ticker-Tick herunter. Ist `0` wenn `completed`.

## BLoC

### Completion-Logik

Die Completion wird an zwei Stellen geprüft – beide prüfen dieselbe Bedingung:

```dart
if (nextPhase == PhaseType.inhale &&
    state.currentCycle >= _pattern.defaultCycles) {
  _ticker?.stop();
  emit(state.copyWith(
    status: SessionStatus.completed,
    fillLevel: 0,
    sessionSecondsRemaining: 0,
  ));
  return;
}
```

**`_onTickUpdated`**: Wenn `_phaseAccumulated >= phaseDuration` und der nächste Übergang zurück zu `inhale` wäre und wir im letzten Zyklus sind → stop.

**`_onPhaseCompleted`**: Identische Prüfung für den öffentlichen Test-Event-Pfad.

Wichtig: `_phaseIndex` wird in `_onPhaseCompleted` jetzt **vor** dem Emit aktualisiert (nicht mehr danach), damit `_sessionSecondsRemaining()` korrekt rechnen kann.

### `_sessionSecondsRemaining(int currentCycle)` (neue Hilfsmethode)

```dart
int _sessionSecondsRemaining(int currentCycle) {
  final cycleSeconds = _pattern.phases
      .fold(0, (int s, p) => s + p.duration.inSeconds);
  var remainingInCycle = 0;
  for (var i = _phaseIndex + 1; i < _pattern.phases.length; i++) {
    remainingInCycle += _pattern.phases[i].duration.inSeconds;
  }
  final completeCyclesLeft = _pattern.defaultCycles - currentCycle;
  return _secondsRemaining() +
      remainingInCycle +
      completeCyclesLeft * cycleSeconds;
}
```

Berechnung: verbleibende Sekunden der aktuellen Phase (`_secondsRemaining()`) + Summe der nachfolgenden Phasen im aktuellen Zyklus + verbleibende vollständige Zyklen × Zyklusdauer. Wird bei jedem Emit in `_onTickUpdated` und `_onPhaseCompleted` neu gesetzt.

### `_calcTotalSessionSeconds(BreathingPattern)` (static, für den Konstruktor)

```dart
static int _calcTotalSessionSeconds(BreathingPattern pattern) =>
    pattern.defaultCycles *
    pattern.phases.fold(0, (int s, p) => s + p.duration.inSeconds);
```

Wird im BLoC-Konstruktor, `_onResetPressed` und `_onPatternSelected` verwendet, da dort `_phaseIndex = 0` und `_phaseAccumulated = Duration.zero` gilt und `_sessionSecondsRemaining()` noch nicht aufgerufen werden kann.

## Signalwege

### Completion-Flow

**Letzter Zyklus endet → `_onTickUpdated` detektiert `nextPhase == inhale && currentCycle >= defaultCycles` → `_ticker?.stop()` → `emit(completed, fillLevel: 0, sessionSecondsRemaining: 0)` → `PlaybackControls` rebuildet: Play-Button ausgegraut, Reset-Button amber → Phase-Label zeigt `COMPLETE`**

### Reset aus `completed`

**Nutzer tippt Reset-Button → `ResetPressed` → `_onResetPressed` → frischer `BreathingState(idle, sessionSecondsRemaining: totalSessionSeconds)` → Phase-Label zeigt `READY`, Session-Countdown zurück auf Gesamtzeit**

### `PlaybackControls` – Redesign

**Vorher:** Asymmetrischer Row (Play-Button links, Reset rechts). Im `completed`-State wurde der Play-Button durch einen großen Replay-Button ersetzt.

**Nachher:** Symmetrischer Row – Settings-Button links, Play/Pause in der Mitte, Reset rechts. Alle drei Elemente immer sichtbar.

```
[Settings 32px] [8px] [Play/Pause 72px] [8px] [Reset 32px]
```

Die Symmetrie (Settings = Reset = 32px icon, je 48px touch target) hält den Play-Button stets visuell zentriert.

**`completed`-State:**
- Play-Button: `colors.textHint` + `onPressed: null` (disabled)
- Reset-Button: `Colors.black` icon auf `colors.signal` Hintergrund (`IconButton.styleFrom(backgroundColor: colors.signal)`)

**Settings-Button:**
- `Icons.settings`, `colors.textHint`, `onPressed: onSettings` (optional, derzeit `null`)
- Infrastruktur für den späteren Edit-Mode; disabled-Darstellung signalisiert „noch nicht aktiv"

### Phase-Label: `READY` / `COMPLETE`

```dart
String _phaseLabel(SessionStatus status, PhaseType phase) {
  if (status == SessionStatus.completed) return 'COMPLETE';
  if (status == SessionStatus.idle || status == SessionStatus.paused) {
    return 'READY';
  }
  return switch (phase) { ... };
}
```

`READY` im Idle/Paused-State signalisiert Bereitschaft. `COMPLETE` im Completed-State bestätigt den Abschluss. Während der Session (`playing`) zeigt der Label den aktuellen Phasennamen (INHALE, HOLD, EXHALE).

### Theme-Integration: `BreathingAnimationWidget` und `PatternDropdown`

Beide Widgets haben zuvor hardcodierte Hex-Farben verwendet (`Color(0xFF4A9EBF)` etc.). Diese wurden auf `context.bTheme.colors` umgestellt:

| Vorher | Nachher |
|---|---|
| `Color(0xFF4A9EBF)` (Füllfarbe) | `colors.accent` |
| `Color(0xFF1A2A3A)` (Oberfläche) | `colors.surface` |
| `Color(0xFF0D1520)` (Dim-Fläche) | `colors.surfaceDim` |
| (kein Border) | `colors.signal` (1.5px Border auf Animation + Circles) |

Die Signal-Farbe (Amber) wird jetzt als Border auf dem Animations-Rechteck und den Kreisen verwendet. Dies gibt der Animation einen konsistenten visuellen Rahmen.
